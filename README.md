# Play Store Competitor Tracker

Щодня знімає стан сторінок конкурентів у Google Play, знаходить зміни (назва, описи, скріншоти, іконка, версія, ціни IAP...) і сплески росту, шле звіт у Slack.

Принцип: **git = база даних.** Кожен день бот комітить нові snapshot-и, тож повна історія змін будь-якої апки доступна через історію файлу в GitHub.

## Що де лежить

| Файл | Що це |
|---|---|
| `config.yaml` | список апок, ринків і порогів алертів — **єдине, що треба редагувати** |
| `data/snapshots/<app>/<ринок>.json` | останній стан сторінки (історія в git) |
| `data/metrics.csv` | щоденні інсталли, рейтинги, відгуки — можна відкрити в Google Sheets |
| `data/changes.jsonl` | журнал усіх знайдених змін |
| `reports/<дата>.md` | щоденний звіт |

## Запуск за 15 хвилин

1. **Створи приватний репозиторій** на GitHub і залий туди цю папку
   (найпростіше: на github.com → New repository → "uploading an existing file", перетягни всі файли, включно з папкою `.github`).
2. **Відредагуй `config.yaml`**: перевір package names (відкрий `https://play.google.com/store/apps/details?id=<id>`), додай конкурентів.
3. **Slack (необов'язково):** у Slack створи Incoming Webhook (api.slack.com/apps → Create App → Incoming Webhooks → Add to channel), скопіюй URL.
   У репозиторії: Settings → Secrets and variables → Actions → New repository secret, назва `SLACK_WEBHOOK_URL`.
4. **Перший запуск:** вкладка Actions → `daily-competitor-tracker` → Run workflow.
   Перший день лише збереже baseline. Зміни почнуть з'являтися з другого дня, сплески росту — після ~4 днів історії.

Далі все працює саме щодня.

## Локальний запуск

```bash
pip install -r requirements.txt
python run.py          # без SLACK_WEBHOOK_URL звіт просто ляже в reports/
python -m pytest -q    # тести
```

## Як читати сигнали

- **Сплеск рейтингів** — приріст оцінок за добу в рази вищий за звичний. Найкращий безкоштовний проксі сплеску інсталлів (UA-кампанія, фічеринг, вірусність). Дивись, що вони змінили за попередні 2 тижні.
- **Назва / short description** — ASO-тест або зміна позиціонування. Зміна лише в одному ринку = локальний експеримент.
- **Скріншоти / іконка** — тест креативів сторінки.
- **Діапазон цін IAP** — зміна монетизації (нові плани, підняття цін).
- **Версія** — частота релізів показує темп розробки.
- `realInstalls` — оцінка, гранулярніша за бакет, але не точна цифра. Дивись на динаміку, а не на абсолют.

## Обмеження

- Google Play не дає точних інсталлів і виручки. Тут проксі, а не цифри Sensor Tower.
- Скрапінг сторінки, не офіційний API: якщо Google змінить верстку, оновлюй `google-play-scraper` (`pip install -U`).
- Custom store listings (аналог CPP) так не знайти — тільки через посилання в рекламі.
